# TakeDeck TD-01 — 요구사항 정의서

책상 위 작은 USB 촬영 컨트롤러. 물리 버튼으로 OBS Studio의 녹화를 시작·중지하고, 촬영 중이면
빨간 표시등이 켜지고, 작은 OLED에 촬영 경과 시간과 연결 상태가 보인다. 장면(Scene) 전환 버튼과
마이크 음소거 버튼을 함께 둔다.

이 문서는 "무엇을 만들고, 무엇을 만들지 않는가"를 고정한다. 구현 구조는
[ARCHITECTURE.md](ARCHITECTURE.md), 실제 검증 결과는 [HARDWARE_VERIFICATION.md](HARDWARE_VERIFICATION.md)에 있다.

---

## 1. 사용자와 사용 상황

| 항목 | 내용 |
|---|---|
| 사용자 | 책상에서 혼자 화면 녹화·강의 촬영을 하는 1인 크리에이터 (이 프로젝트에서는 개발자 본인) |
| 상황 | OBS 창이 다른 모니터·다른 가상 데스크톱에 있어도, 손이 닿는 곳의 버튼 하나로 녹화를 시작·중지하고 싶다 |
| 실패 비용 | 녹화가 안 걸린 채로 촬영을 마치거나, 이미 녹화 중인데 또 눌러 중지되는 것 |
| 전원 | 책상 위 USB 포트 상시 연결. 무선·배터리·상용전원 없음 |

## 2. 기능 요구사항

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-1 | REC 버튼 한 번으로 OBS 녹화를 시작하고, 다시 누르면 중지한다 | OBS `GetRecordStatus`의 `outputActive`가 실제로 뒤집히고, 화면에 반영된다 (호스트 테스트로 확인) |
| FR-2 | 빨간 표시등은 "버튼이 눌렸다"가 아니라 **OBS의 실제 녹화 상태**를 보여준다 | OBS UI에서 직접 녹화를 시작해도 LED가 켜진다 (모의 OBS 연동 테스트로 확인) |
| FR-3 | OLED에 촬영 경과 시간을 `HH:MM:SS`로 표시한다 | 값은 OBS `GetRecordStatus.outputDuration`에서 오며, 4 Hz 갱신 + 기기 내 1초 보간 |
| FR-4 | OLED에 연결 상태를 명시한다 (`USB LINK OK` / `SYNCING` / `LINK LOST` / `WAIT FOR OBS`) | 링크가 끊기면 3초 안에 `LINK LOST`로 바뀐다 |
| FR-5 | 장면 전환 버튼(◀/▶)으로 OBS 프로그램 장면을 순환한다 | 장면 목록은 OBS가 준 순서를 따르고, 양 끝에서 순환한다 |
| FR-6 | MUTE 버튼으로 지정한 오디오 입력을 음소거/해제한다 | 브리지 실행 시 `--mute-input`으로 지정한 입력에만 동작. 미지정이면 기기에 에러를 표시 |
| FR-7 | 통신이 끊기면 상태를 "모른다"고 명시한다 | 링크 단절 시 LED는 점멸(불명), OLED는 `LINK LOST` + `REC ?` |
| FR-8 | 키 입력은 디바운스되고, 한 번 누름은 한 번의 명령이 된다 | 15 ms 안정화 후 1회 이벤트, 홀드 시 반복 없음 |
| FR-9 | 명령이 중복 실행되지 않는다 | 재전송·ACK 유실·브리지 재시작에도 토글이 두 번 실행되지 않는다 (시퀀스 + (세션, 시퀀스) 캐시) |
| FR-10 | 링크가 없을 때 누른 키는 조용히 사라지지 않는다 | 명령을 큐에 쌓지 않고 `NO LINK`를 표시한다 (재연결 후 엉뚱한 동작 방지) |
| FR-11 | USB 연결만으로 동작한다 (별도 전원 없음) | USB 5 V 버스 전원. 전체 소비 < 100 mA |
| FR-12 | 조립 가능한 기성 부품 프로토타입이다 | BOM의 부품만으로 조립되고, 3D 프린트 케이스에 들어간다 |

## 3. 비기능 요구사항

| ID | 요구사항 | 근거 / 수용 기준 |
|---|---|---|
| NFR-1 | 버튼 입력 → OBS 반영 지연 < 150 ms (체감 즉시) | 펌웨어 틱 1 ms, 폴링 250 ms, 명령 즉시 처리 |
| NFR-2 | 전원: USB 2.0 버스 전원(5 V, 500 mA) 이내 | 아래 전원 예산 |
| NFR-3 | 표시 갱신은 상태 변화를 250 ms 안에 반영 | STATE 4 Hz 푸시 |
| NFR-4 | 케이스는 FDM 프린터로 출력 가능하고 나사 4개로 조립 | STL 워터타이트, 간섭 검사 통과 |
| NFR-5 | 인증정보를 저장소에 두지 않는다 | OBS 비밀번호는 환경변수/인자로만 받는다 |
| NFR-6 | 재연결이 자동이다 | 기기 분리/재삽입, OBS 재시작 모두 사람 손 없이 복구 |

## 4. 전원 예산 (5 V USB, 3.3 V 레일)

XIAO RP2040은 USB 5 V(VBUS)를 받아 온보드 LDO로 3.3 V를 만든다. 모든 부하는 3.3 V 레일에서
전원을 받는다. 값은 데이터시트/계산 근거를 함께 적었다.

| 부하 | 전류 | 근거 |
|---|---|---|
| XIAO RP2040 (RP2040 133 MHz, USB 동작, 온보드 전원 LED 포함) | 25–30 mA | RP2040/Pico 계열의 동작 전류대(25 mA @125 MHz) + 보드 LDO·LED 여유 |
| SSD1306 0.96" OLED 모듈 (차지펌프 ON, 평균 표시 내용) | 12–20 mA | Winstar 모듈 규격의 3.3 V 동작, 128×64 전형 소비 |
| 적색 LED 5 mm (220 Ω, Vf 1.85 V) | 6.6 mA | (3.3 − 1.85) / 220 Ω ≈ 6.6 mA |
| 키 스위치 4개 (내부 풀업, 접점 전류) | < 0.1 mA | 3.3 V / 50 kΩ × 4 |
| 합계 (전형) | **≈ 45–57 mA** | — |
| 합계 (LED 점등 + OLED 최대 휘도 가정) | **≈ 65 mA** | — |
| 설계 여유 (20 % + 계측 오차) | **≤ 80 mA** | USB 2.0 100 mA 단일 부하 한도 이내 |

- USB 기술서(descriptor)의 `bMaxPower`는 pico-sdk 기본값인 **250 mA**로 광고된다(코드에서
  `USBD_MAX_POWER_MA`는 SDK가 고정). 실제 소비는 위 표와 같이 100 mA 미만이며, USB 2.0 호스트가
  enumeration 전에 보장하는 100 mA 안에서도 동작한다.
- 3.3 V 레일 최대 부하 ≈ 57 mA → XIAO 온보드 LDO(≥ 200 mA급)에 충분한 여유.
- 돌입 전류: OLED 차지펌프와 100 nF 디커플링으로 완화. 별도 소프트스타트는 두지 않는다(프로토타입 범위).
- **측정하지 않은 값**: 위 전류는 데이터시트·계산 기반 추정이며, 실기에서 USB 전류계로 측정하지 않았다
  (HARDWARE_VERIFICATION.md 참조).

## 5. 범위 밖 (명시적 제외)

- 무선(Bluetooth/Wi-Fi), 배터리, 충전 회로, 상용전원 어댑터
- 오디오 입출력(마이크 전원, 오디오 인터페이스) — MUTE는 OBS의 입력 음소거 API만 사용
- 자체 USB HID 키보드 에뮬레이션 (OBS 단축키 주입 방식) — 채택하지 않은 이유는 ARCHITECTURE.md §2
- 방수·IP 등급, 인증(CE/FCC), 양산용 PCB 설계·조립
- OBS 이외의 프로그램(줌, OBS 이외 레코더) 제어

## 6. 완료 정의 (Definition of Done)

1. `firmware/`가 크로스 컴파일되어 `.elf`/`.uf2`가 생성된다 — **완료**
2. 펌웨어 로직 호스트 테스트가 통과한다 — **완료 (130 checks)**
3. `host/` 브리지가 pytest로 검증된다 (모의 OBS + 펌웨어 시뮬레이터 end-to-end 포함) — **완료 (37 tests)**
4. `enclosure/`가 파라메트릭 원본 + STL을 만들고 간섭 검사를 통과한다 — **완료 (22 checks)**
5. `preview/`가 브라우저에서 실제로 뜨고 조작 가능하다 — **완료 (headless Chromium 실행, 콘솔 에러 0)**
6. 실기 조립·플래시·OBS 연동은 **미완료**이며, 인수 테스트 목록으로 남긴다.
